# BombCrash 開発・設計ドキュメント

本書は、プロジェクトの概要、実装済み機能、設計上の特徴と現状の課題をまとめたものです。ゲーム内の進め方と操作については [ゲーム説明書](README.md)、物語については [あらすじ](story.md) を参照してください。

## 1. 作品名・概要

**BombCrash** は、カウントダウンで爆発する敵性爆弾を凍結爆弾で撃破し、ウェーブを生き延びる2Dアクションゲームです。敵を倒して資源を集め、装備やスキルを活用しながらより先のウェーブを目指します。

物語の導入では、父の失踪と謎の爆弾の出現を受け、主人公が自作の凍結爆弾を手に戦い始めます。あらすじは [story.md](story.md) を参照してください。

## 3. ゲームの特徴・主要機能

- **爆弾バトル**：プレイヤーは着弾位置を調整して爆弾を投げます。爆弾は所持数制で、時間経過により補充されます。敵にはHPと爆発までのカウントダウンがあり、撃破時にはスクラップをドロップします。
- **ウェーブ進行**：`EndlessWaveRule` の設定から敵の出現パターンを組み立てます。ウェーブが進むにつれ出現間隔や敵のHPが変化し、定期的にスタンピードが発生します。
- **スキルと必殺技**：オトモに装備したスキルを使用でき、クールタイムを管理します。スキルの設定に応じて自動発動も行います。必殺技には個別の使用可能状態があります。
- **育成・リザルト**：装備による能力強化、スクラップや知見ポイントの獲得、到達ウェーブや獲得資源のリザルト表示を実装しています。一定の到達ウェーブを条件にオトモが解放されます。
- **画面・演出**：ホーム、ゲーム、ローディング、ストーリー、ボスなどのシーンがあり、画面遷移、フェード、カットイン、サウンド、カメラ振動を組み合わせています。

ガチャ関連のスクリプトは存在しますが、未実装部分があるため現行のホーム画面ではボタンが無効化されています。利用可能な機能として案内しないよう注意してください。

## 4. 技術的な工夫・設計

### データと処理の分離

ゲームデータの多くを ScriptableObject として管理しています。`PlayerStatusSO`、`EnemySO`、`BossSO`、`BombSO`、`SkillSO`、装備データ、`EndlessWaveRule` などをコードから分離し、敵のステータスやウェーブ構成を Unity Editor 上で調整できる構成です。データベース用アセットはスキルや装備データの一覧を管理します。

### ウェーブデータの生成

`WaveGenerator` は `EndlessWaveRule` と敵ごとの出現設定を参照して、ウェーブ時間、出現間隔、スタンピード設定、出現候補を生成します。`WaveManager` が進行と UI 更新を管理し、`EnemySpawnController` が敵をフィールドに配置します。これにより、ウェーブごとの個別データを固定で列挙せず、ルールと敵データから進行を組み立てています。

### 役割ごとのスクリプト構成

- `Scripts/SO`：ゲームパラメーターやアセットデータの型
- `Scripts/System`：プレイヤー、爆弾、敵、ウェーブ、スキル、サウンドなどのゲーム処理
- `Scripts/UI`：ホーム、ゲーム中 HUD、装備、リザルトなどの表示と UI 操作
- `Scripts/Define`・`Scripts/Interface`：共通定義と `IEnemy` などの共通インターフェース

入力のすべてが UI 層に集約されているわけではなく、移動・投擲などは各ゲーム処理のスクリプトが入力を読み取ります。シーン遷移ではローディングシーンを介し、次のシーンを非同期で読み込みます。

### ゲーム進行の例

1. ホーム画面から出撃し、ローディングを経由してゲームシーンへ移動します。
2. `GameSystem` がプレイヤーと、解放済みの場合はオトモを生成します。
3. `WaveManager` がウェーブ設定をもとに進行を開始し、敵を出現させます。
4. プレイヤーが爆弾を投げ、敵を撃破するとスクラップと討伐数が更新されます。
5. 敵のカウントダウンが尽きるとゲームオーバーとなり、リザルトに到達ウェーブと獲得資源を表示します。

## 5. 工夫した点・課題と改善

ゲームバランスに関わる値を ScriptableObject に分離したこと、ウェーブの出現候補をルールから生成することが、調整しやすさにつながっています。履歴上も、ホーム画面で操作方法を確認できるようにした変更、装備スロットのアニメーション初期化、削除済みアセットを参照していた箇所の修正、UI の段階的な刷新が行われています（例：`50113ad`、`9e10965`、`d935937`）。

現状で明確な制限はガチャ機能です。最新の関連コミット `87f710b` では、未実装箇所があるためホーム画面のガチャボタンを押せない状態にしています。再度有効化する前に、抽選・コスト処理・結果と所持品への反映・UI 表示までを一連で確認する必要があります。その他の調整では、難易度曲線、ウェーブ進行、シーン遷移、リザルトの資源加算を複数のプレイ条件で検証することが改善候補です。
